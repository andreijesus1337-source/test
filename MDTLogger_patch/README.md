# MDTLogger — правки

Патч на два файла мода **MDTLogger**:
`scripts/4_World/MDTLogger/MDTPlayerLogger.c` и `scripts/4_World/MDTLogger/MDTLocale.c`.

## 1. Чат в Discord - только ник + сообщение

В `LogChat()` сообщение, уходящее в Discord, раньше выглядело так:

```
:speech_balloon: **Сообщение в чате**
Игрок: `hazard` (`76561199571548476`)
Сообщение: `АНДРЕЙ ХУЙ`
Позиция: `4684 / 339 / 9869`
```

Теперь — только ник и сам текст:

```
:speech_balloon: **hazard**: АНДРЕЙ ХУЙ
```

Убрано: SteamID, лейбл "Сообщение:", позиция игрока, отдельная строка-заголовок.
**Файловый лог чата** (пишется в `chat.log`) не трогали - там по-прежнему
полная информация для модерации, меняется только то, что видно в Discord.

## 2. Уведомления о начале/конце шторма EVRStorm

Новая категория лога **"storm"** - работает по той же схеме, что и все
остальные категории мода (chat, death, connect и т.д.):

- `MDTLoggerConfig.EnableStormLog` (вкл/выкл, по умолчанию true)
- `MDTDiscordConfigs.StormConfig` (отдельный вебхук именно под шторм)
- Пишет в `$profile:MDT/MDTDiscord/storm.log`
- В Discord: `:cloud_lightning: **Начался шторм EVRStorm!**` при старте
  и `:white_check_mark: **Шторм EVRStorm закончился.**` при завершении.

Зовётся не из самого MDTLogger, а из **EVRStormOverride.c**
(`MDTPlayerLogger.LogStormEvent("start")` / `("end")`) - см. отдельный
коммит с этим файлом. MDTLogger просто предоставляет готовую функцию,
конкретный шторм-мод её вызывает в нужные моменты.

### Как включить у себя

1. Поставьте оба файла из этого патча вместо оригинальных в PBO
   мода MDTLogger, пересоберите/перезалейте.
2. Откройте `profiles\MDT\MDTDiscord\discord_configs.json`:
   - Если файла ещё нет - он создастся сам при первом запуске сервера,
     уже с полем `StormConfig`, останется только вписать `WebhookUrl`.
   - Если файл уже есть (сервер и так работал) - новое поле `StormConfig`
     само в него не допишется (мод пересохраняет файл только если он
     отсутствовал). Добавьте вручную блок:
     ```json
     "StormConfig": {
         "WebhookUrl": "https://discord.com/api/webhooks/...",
         "BotName": "MDT Logger",
         "AvatarUrl": ""
     }
     ```
     (впишите свой реальный webhook URL) - либо просто удалите файл,
     он пересоздастся целиком со всеми категориями по умолчанию.
3. `EnableStormLog` в `logger_config.json` не требует правки - подставится
   `true` по умолчанию сам, даже если файл уже существует и этого поля
   в нём нет.

### Важный момент по надёжности

Начало шторма (`EndPhaseServer` не при чём, там `InitPhaseServer` -
подтверждено логом сервера) - железно рабочее. А вот конец шторма
завязан на переопределение метода `EndPhaseServer()` в `EVRStorm` -
его точное существование и имя НЕ подтверждено исходником (в отличие
от `InitPhaseServer`/`MidPhaseServer`, которые точно есть), а подобрано
по аналогии (стандартная схема Init/Mid/End у ивентов Namalsk). Если
после сборки будет ошибка компиляции именно на этом месте - пришлите
её текст, поправим на точное имя метода.
