# Apocalypse Weather (DayZ mod)

Мод принудительно устанавливает и удерживает "апокалиптическую" погоду
**по всей карте сервера**: плотная низкая облачность, ливень/гроза, туман
и сильный ветер, без периодов ясного солнечного неба.

## ⚠️ Статус: пепел и красное небо временно отключены

На тестовом сервере сборка с `CfgCloudlets` (пепел) и `CfgWorlds >
ChernarusPlus > Weather > Overcast` (красное небо) вызывала краш сервера
при старте (обрыв RPT без текста ошибки сразу после разбора конфигов —
характерный признак невалидного/сломанного `config.bin`, а не ошибки
скрипта). Оба блока **убраны из `config.cpp`**, а эффект пепла отключён
флагом (`ApocalypseWeatherAshConfig.ENABLED = false` в
`ApocalypseWeatherAsh.c`), чтобы основная погода (дождь/туман/ветер/
облачность — надёжная, проверенная часть) точно работала без крашей.

Возвращать пепел/небо нужно по одному блоку за раз, тестируя после
каждого — так, если краш вернётся, будет сразу понятно, какой именно
блок виноват.

Погода в DayZ — глобальный параметр карты (`GetGame().GetWeather()`),
поэтому изменение применяется сразу ко всей карте целиком, а не к
какой-то отдельной зоне.

## Как это работает

- `Source/ApocalypseWeather/5_Mission/ApocalypseWeather/ApocalypseWeather.c`
  расширяет (`modded class`) `MissionServer` и в `OnInit()`:
  1. выключает встроенную динамическую систему погоды сервера
     (`weather.MissionWeatherSuppress(true)`), чтобы она не "стянула"
     погоду обратно к ясной;
  2. задаёт целевые значения и допустимые диапазоны для облачности,
     дождя, тумана и ветра;
  3. раз в `ENFORCE_INTERVAL` секунд повторно "прибивает" эти значения —
     на случай ручных админ-команд погоды или сторонних плагинов.
- Все параметры (интенсивность, диапазоны, интервал) вынесены в класс
  `ApocalypseWeatherConfig` в начале файла — их можно менять без знания
  Enforce Script.
- `Source/ApocalypseWeather/5_Mission/ApocalypseWeather/ApocalypseWeatherAsh.c`
  содержит код эффекта пепла (`PlayerBase::EEInit/EEKilled`), но сейчас
  **отключён** флагом `ApocalypseWeatherAshConfig.ENABLED = false` — см.
  раздел про статус выше.

## Как вернуть пепел и красное небо

1. **Красное небо (`CfgWorlds`)**: добавьте обратно в `config.cpp` блок
   `CfgWorlds > ChernarusPlus > Weather > Overcast > Overcast7/8/9`
   (сохранён в истории git — коммит "Add ash particle effect and red
   sky tint for ChernarusPlus"), пересоберите PBO, протестируйте запуск
   **отдельно**, без блока пепла. Перед этим сверьте реальные названия
   полей (`colorSky`, `colorHorizon` и т.д.) и `requiredAddons` карты
   через Workbench Config Viewer — именно тут была наибольшая
   неуверенность.
2. Если сервер стартует нормально — добавьте блок `CfgCloudlets` (тоже
   в истории git) и включите `ApocalypseWeatherAshConfig.ENABLED = true`,
   снова пересоберите и протестируйте отдельно.
3. Если краш вернётся на каком-то из шагов — вы будете точно знать, какой
   блок виноват, и это будет видно в Workbench при попытке собрать PBO
   (реальная ошибка компиляции конфига, а не "тихий" краш сервера).

Погодная логика (`ApocalypseWeather.c`) написана по стандартному и
хорошо задокументированному в комьюнити API класса `Weather`
(`GetOvercast/GetRain/GetFog/GetWind`, `SetLimits`, `Set`,
`MissionWeatherSuppress`) — уверенность в этой части высокая, и именно
она сейчас единственная активная часть мода.

Пожалуйста, соберите и протестируйте мод у себя перед использованием на
живом сервере.

## Сборка PBO

1. Установите **DayZ Tools** через Steam (нужен инструмент `AddonBuilder`,
   входит в комплект).
2. Скопируйте папку `Source/ApocalypseWeather` в вашу P:\ драйв-структуру
   (или используйте AddonBuilder напрямую на этой папке — она уже содержит
   `config.cpp` и `5_Mission/...`, как требует Addon Builder).
3. Запустите AddonBuilder, укажите:
   - Source folder: `Source/ApocalypseWeather`
   - Destination: `@ApocalypseWeather/Addons/ApocalypseWeather.pbo`
4. Убедитесь, что бинаризация прошла без ошибок.

Итоговая структура мода для клиента/сервера должна выглядеть так:

```
@ApocalypseWeather/
├── mod.cpp
└── Addons/
    └── ApocalypseWeather.pbo
```

## Установка на сервер

Добавьте мод в параметры запуска сервера (`serverDZ.cfg` / командная строка):

```
-mod=@ApocalypseWeather
```

Мод серверный (влияет на `MissionServer`), поэтому клиентам достаточно
подписаться/скопировать `@ApocalypseWeather`, но саму логику выполняет
сервер — распространять через Steam Workshop не обязательно, если мод
используется только на своём сервере (можно подключать как локальный мод).

## Настройка интенсивности

Откройте `Source/ApocalypseWeather/5_Mission/ApocalypseWeather/ApocalypseWeather.c`
и поменяйте значения в `ApocalypseWeatherConfig`:

| Параметр | Что делает | По умолчанию |
|---|---|---|
| `ENABLED` | вкл/выкл мод | `true` |
| `OVERCAST_MIN/MAX` | плотность туч (0=ясно, 1=максимум) | 0.85 / 1.0 |
| `RAIN_MIN/MAX` | интенсивность дождя (0=нет, 1=ливень) | 0.6 / 1.0 |
| `FOG_MIN/MAX` | плотность тумана (0=нет, 1=максимум) | 0.35 / 0.75 |
| `WIND_MIN/MAX` | сила ветра (0=штиль, 1=ураган) | 0.4 / 0.85 |
| `TRANSITION_TIME` | сек., за которые погода переходит к цели | 5.0 |
| `ENFORCE_INTERVAL` | как часто (сек) заново применять погоду | 60.0 |

В `ApocalypseWeatherAsh.c` есть отдельный `ApocalypseWeatherAshConfig`
(сейчас `ENABLED = false`, см. "Как вернуть пепел и красное небо" выше).

После любых изменений нужно пересобрать `.pbo`.

## Возможные доработки (не включены)

- Молнии/грозовые вспышки в DayZ появляются автоматически при высоких
  значениях облачности+дождя — отдельно триггерить их не нужно.
- Красная цветокоррекция всего экрана (пост-эффект, а не только
  небо/туман) потребовала бы кастомного post-process/LUT-ассета через
  DayZ Tools.
- Собственные текстуры для пепла (а не переиспользование существующих)
  потребовали бы Object Builder / TexView2.
